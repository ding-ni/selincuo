使用说明
本文件可整体交给 Codex 执行。你需要依据本任务修改真实项目、完成必要联调并提交 Git，而不是再输出一份泛泛的建议或待办。
正文按“前端修复 → 后端修复 → 联调验收 → 清理与 Git 交付”排列。涉及接口和数值的前端功能，必须等待对应后端完成后才能判定通过；可以先约定接口，并行实施不冲突的工作，不能用假数据或前端改标签代替后台修正。

适用仓库：https://github.com/ding-ni/selincuo

界面依据：用户提供的普通窗口大屏、全屏大屏、模型方案与率定、过程与状态截图。
执行基准：实际最新仓库、实际运行工作区与真实资料。上述提交是问题定位依据，不能覆盖用户后续更新。

第一部分  总体目标、范围与执行约束
================================================================

一、最终交付目标

1. 平台保留一套已经采用、参数完整、能够连续运行的内置方案。它在方案列表中正常存在；不在各页面反复强调“默认方案”“标准历史方案”“研究候选”。
2. 用户主要决定业务事项：选择方案和时期、查看或调整参数、率定、模拟、查看成果、维护资料。
3. 资料整理、气象订正、输入匹配、初始条件安排、空间归属、计算衔接由后台负责，正常操作不要求用户选择内部 INPUT、AGG、修订、基线或冻结对象。
4. 首页在普通窗口与全屏下都能完整展示核心信息，地图清楚、数值一致、播放连贯。监测资料页保持当前简洁风格。
5. 主站历史观测、四岸资料、站点降水、气象驱动和模型成果各有明确用途。观测缺测不应切断具备完整驱动及初态的模拟。
6. 对排水归属、基准登记和模型输入中的实际问题，完成相应数据与计算处理，再调整界面表达。
7. 更新资料后可以继续率定或模拟；历史结果仍对应其实际参数、输入和空间定义。
8. 交付实际可运行的前后端修改、必要配置、实际验证结果以及已推送的 Git 提交。本轮不制作 EXE。

二、开始前只做必要核对

1. 读取项目 AGENTS.md、当前分支、工作区改动和相关运行记录。保护用户未提交的改动，不执行 reset --hard 或无条件覆盖。
2. 确认本机实际运行目录、数据库、原始观测、GIS、DEM、气象资料、空间产物和结果路径。仓库内源码与历史记录不能替代本机真实资料。
3. 核对当前正在运行的下载和模型任务。已有记录涉及 2020—2022 年气象补充，但实际状态以运行环境为准。不得假定已结束，也不得为改前端随意终止任务、重启服务或重复下载。
4. 核对每个任务编号的现状。后续提交已经解决的条目，只验证其实际效果；不重复重构已经正确的功能。
5. 简要列出将修改的模块和跨层依赖后直接执行，不因普通实现选择反复要求用户确认。
6. 如果某项关键原始资料确实不可获得，明确阻塞的具体计算及所需资料，同时完成其余可执行任务。不能把整轮工作停在笼统的“资料不足”。

三、必须遵守的实施约束

1. 保留现有真实湖形标识、当前业务导航、连续模拟内置方案、采用参数、监测独立性、播放缓存与预取、资料增量更新、成果回收等已经完成的能力。
2. 不恢复无用的工作模式切换、使用帮助入口、运行维护说明页和跨页面默认方案横幅。轻量配置若确有必要，放在对应业务页面。
3. 不打包 EXE，不重复全量备份，不为每项改动生成大批阶段目录、候选方案、截图副本或验收文档。
4. 文案、样式和查询优化不重跑全时段模型。真正改变空间归属、驱动、初态或计算逻辑时，才执行与影响范围相匹配的数值核验。
5. 不填造观测、地形、零点高程、排水连接或模拟结果。不得把缺测替换成零，不得把已有成果裁剪当成一次新模拟。
6. UI 可以简洁；计算事实必须正确。不能仅删除提示、隐藏区域、扩大色差、篡改合计或伪装状态来宣布问题解决。
7. 复用现有模块和数据结构，优先做有边界的修改。除非现有结构明确无法满足要求，不引入新的框架、服务或并行资料库。
8. 清理采用项目现有可恢复方式，保护唯一原始资料和仍被引用的输入、状态、参数。不得以清理为名永久批量删除或清空回收站。
9. 用户已经要求完成修改后上传 Git。按正常流程提交推送，不强推，不上传原始气象大文件、数据库、凭据、依赖目录和安装包。
10. 本任务编号是开发实施索引，不得作为新的“工作模式”“候选状态”或技术标签展示给平台用户。

【F01】湖情总览：普通窗口内容越界、全屏间距失控

问题：
普通窗口中四岸观测及右侧湖泊收支第二行被下方过程图遮挡；全屏时“入湖合计”与收支之间留白过大。当前大屏固定行高与比例轨道并存，左右栏共同使用 justify-content:space-between，自然内容高度与实际分配高度不匹配。

解决方法：
1. 保留“左侧雨情与观测—中间横向流域地图—右侧来水与收支—下方过程图—底部时间轴”的总体结构。
2. 重设主区、图表区和侧栏的高度分配。根据容器真实可用宽高采用普通/紧凑密度，不只依赖一个 max-height:800px 断点。
3. 左右栏取消用 space-between 分配大段 section 间距。使用明确的内容行、固定合理间隔和必要最小高度。
4. 左侧四岸完整四站、右侧收支完整四项必须在默认界面可见。四岸可采用紧凑 2×2 布局。
5. 右侧来水分量、合计与收支连续排布。剩余空间分配给地图、图表和有效信息区，不用无意义说明或新模块填充。
6. 精简重复时间、资料最新日期和冗余小字，释放空间。不得隐藏关键数值、默认折叠、裁切溢出或缩小到难读字号。
7. 全屏退出后尺寸和图表必须恢复正确，不能保留旧宽高缓存。窄屏采用明确响应布局，不允许内容覆盖。

主要位置：
frontend/src/dashboard.css
frontend/src/Dashboard.vue
必要时检查外层应用容器和图表 resize 处理。

后端依赖：
无须修改水文计算；与 F02 的卡片内容一起调整。

完成判据：
使用用户实际普通窗口与全屏，并检查一个曾触发失败的浏览器缩放条件。四岸最后一行、收支四格的元素边界均在各自面板内，与下方图表不相交；全屏无被强行拉开的空档。不能只以“没有页面滚动条”判断通过。


【F02】湖情总览：观测日期、来水组成与水量单位清楚一致

问题：
四岸有值时也仅显示“当日有记录”；早于资料起点的日期被称为缺测；历史回放混入资料库最新记录日期。截图四河显示合计 108.75 m³/s，而入湖合计为 108.83 m³/s；当前列表过滤了 fringe，但总量仍包含它。

解决方法：
1. 当日观测卡只使用所选日的真实值，不用最新有效值替代。资料库最新记录日期移到站点详情。
2. 四岸有值时显示各站原基准的水位/水尺读数和单位；没有测量基准时，不转成伪绝对高程。
3. 区分“早于资料起点”“资料期间无有效日值”“有效记录”“读取失败”。缺少建站日期时，不写“尚未建站”。
4. 回放 2024-06-19 时，四岸早于现有记录起点应明确表示该时段无记录；不能据此断言南岸站没有资料。
5. 采用后台提供的真实入湖分量。应显示的湖周直接来水必须列出，或明确区分四河小计与总入湖量，使组成与总量可以核对。
6. 不把差额塞进某条河，不把未完成排水判定的区域临时改名为湖周来水。杜加属于对应支流内部断面，不额外重复加总。
7. 区分流量 m³/s、当日水量 万m³或百万m³、降水 mm、水位 m及涨落 cm；统一小数位和千分位规则。
8. 湖泊收支使用同一天、同一结果的入湖水量、湖面降水量、蒸发量和蓄水变化。正负号与名称一致。
9. 首页湖面雨量与模型实际采用的湖面降水一致；原始气象值与订正后模型值不得混称同一指标。
10. 清除“旧假定”“旧统计”“窗口初始化评价”等遗留研发文案，但保持数值的真实来源。

主要位置：
frontend/src/Dashboard.vue
frontend/src/dashboard.mjs
观测摘要与结果摘要相关接口调用。

后端依赖：
B01、B02、B04、B06、B08。

完成判据：
有效日、资料起点前、真实缺测日分别正确；四岸显示真实值；分量与合计在显示舍入范围内一致；流量积分与日水量使用一致时段；同一画面不混用多个日期或结果。


【F03】流域地图：图层优先级、配色、真实几何与控制项

问题：
用户此前指出图层叠加、湖周高亮范围、专题与底色竞争、分区边界和颜色辨识度存在问题；本轮深色分区仍接近。已修部分需保留，不能恢复旧的叠加错误。

解决方法：
1. 明确底图、地形、专题填色、河网、站点、边界、标签与选中层的顺序。
2. 开启地形或数值专题时，以该专题着色作为主要面表达；流域范围用边界保留，不能再叠一层不透明分区填色遮住专题。
3. 湖周直接入湖区使用后台生成的真实几何。选中时只高亮该区域，不能把全流域底面全部高亮。
4. 深色主题使用专门的分区颜色和边界强度，保证四河、湖区与图例对应。不要仅把浅色填色整体降低透明度。
5. 数值专题采用真实空间数值和适当范围。零、缺测、正负量有不同语义，不能为增强视觉差异改数。
6. 图层控制按用途分组：专题变量、叠加图层、视图操作。不要把流域站网、日降水、地形等不同层级选项无序并列。
7. 杜加作为站点/内部控制断面表达，不与四个主要流域并列成第五条入湖河。
8. 保留横向地图比例与全流域范围适配。真实小斑块通过定位辅助，不扩大地理面积。
9. 已无业务作用的低动态模式或多余下拉项不再出现在日常操作中。

主要位置：
frontend/src/ScreenMap.vue
frontend/src/dashboard.css
现有地图专题、图例和几何读取模块。

后端依赖：
B08、B09；当前正确的地图交互可先保留，归属修正完成后同步采用真实新几何。

完成判据：
分区、地形、降水和状态专题逐一切换后，主要填色和图例一致；湖周选择范围正确；选中层不被覆盖；不同图层不改变计算数值或区域面积。


【F04】时间轴、过程图与回放连续性

问题：
年刻度和首末日期按等距文字排列，实际日期间隔不等；过程图边缘日期被截断；旧问题包括播放中出现居中加载、日降水突然资料不足和日期不同步。

解决方法：
1. 时间轴刻度按真实时间位置放置，与滑杆使用同一日期序列。不能按观测有效日压缩连续模拟时间轴。
2. 首日、年初、任意中间日和末日的日期框、滑杆、游标、卡片、地图一致。
3. 两张过程图统一时间范围和刻度策略。多年总览可显示年月，悬浮保留完整日期；首末标签不裁切。
4. 保留已有整帧切换、缓存、有限并发、预取和过期请求保护。不要重新引入逐块更新造成的跨日期拼接。
5. 加载下一帧时保留上一完整画面，使用不遮挡数据的局部状态；保持“当前显示日期”和正在请求日期清楚，不把旧图标成新日。
6. 区分请求失败、缓存未命中与真实驱动缺口。临时尚未返回不能显示“资料不足”；真实缺口不能补零或无限沿用前一天。
7. 普通和全屏切换后保留所选日期、主题、图层与播放状态，图表及时重排。

主要位置：
frontend/src/Dashboard.vue
frontend/src/Chart.vue
frontend/src/dashboard.css
现有帧缓存、预取和日期工具模块。

后端依赖：
B04、B05、B06、B09；接口必须明确当前帧日期、完整性和真实缺口。

完成判据：
检查首末日、跨年刻度、连续播放和快速拖动。画面始终对应同一实际日期；无居中遮挡式加载；旧响应不覆盖新选择；已具备完整驱动的日期不因请求顺序被误称缺资料。


【F05】站点监测与监测资料：保留观测、按需分析、局部处理异常

问题：
“统计偏移分析”被用作替换观测的资料视图，南岸无平移候选时曲线为空；五站缺共同日可能全部不显示；隐藏分析组件提前执行；多个状态被混写为“时变或资料不足，零点待核”。

解决方法：
1. 保留用户认可的监测资料页总体风格，不重新增加全局方案、修订、成果覆盖等信息。
2. 站点监测展示站点读数、观测时段、站点过程和可用情况；不重复模拟回放，也不要求选择模型成果。
3. 原始记录、整编日值与站间差值分析分别表达。分析不可用时保留原始值和日值，仅不生成相应平移对照线。
4. 前端保留每站的观测、分析结果及具体原因，不只提取 rows 后丢弃状态。
5. 默认展示各站可用过程；共同参考日涨落是单独视图。没有五站共同日时，可以看本站过程及与主站的双站对照，不能偷偷采用不同参考日却称同一基准。
6. 资料可用性、水位基准、站间差值分析分开表达；正常视图只显示当前需要的简短状态，细节按需打开。
7. 分析区首次打开才挂载或请求；关闭状态不调用完整诊断。图表与分析等待分开，一个站失败只影响该站。
8. 保留上一成功图并清楚标识其时期；取消或丢弃过期响应。切出切回复用仍有效的查询结果。
9. 状态文案具体到“所选日期无记录”“日均资料不足”“无同期配对”“差值随时段变化”“零点高程未登记”，不能混成一个模糊结论。
10. 日常页面不展示 quality-v2、legacy、用户撤回确认等内部历史过程；必要的质量方法说明放详情。
11. 提供方便的日期范围选择；查询四岸开始前的时期时，可便捷转到已有资料时段，不把这种情况显示成接口异常。

主要位置：
frontend/src/MonitoringWorkspace.vue
frontend/src/ShoreComparison.vue
frontend/src/shore-comparison.mjs
frontend/src/DatumDiagnostics.vue
站点监测相关组件。

后端依赖：
B01、B02、B03。

完成判据：
南岸在实际有观测时段能查看原值/日值；无分析候选不抹掉观测；一站失败或无共同日不清空其他站；折叠状态不请求完整分析；切换模型方案不改变监测资料来源。

【F06】模型方案与率定：表单围绕业务，率定入口明确

问题：
气象资料下拉框暴露原始/订正等内部输入版本；起算湖位要求用户理解和填写内部初始条件；参数范围列出全部空间分区；率定设置只是细小折叠箭头。

解决方法：
1. 主表单保留方案名称、预热期、率定期、评价期、采用参数和明确操作。使用自然起止日，包含末日与后台右开时间边界由程序转换。
2. 删除日常“气象资料版本”选择。时期确定后，由后台自动核验并解析所需资料；界面显示可用范围或具体缺口。
3. 初始条件默认自动安排，可查看采用日期和数值。必须人工覆盖时放高级计算设置，不要求普通用户手写来源说明。
4. 参数按产流、汇流、积雪、冰川和湖泊分组。默认显示当前采用的有效值。
5. 分区入口只呈现真正存在独立参数的范围，如“杜加站上游参数”。共用值与分区覆盖值关系明确，不把全部 partition 当成必须选择的菜单。
6. 采用参数、人工编辑草稿、本次率定初值保持清楚。修改下一次率定初值不能悄悄改变已经采用的参数。
7. 将“率定设置”改成真正按钮，置于试算和开始率定附近，打开专门面板。显示参与参数、初值、上下限、目标、预算等实际需要的内容。
8. 按钮有清楚点击范围、焦点和展开状态；关闭重开不丢失修改。沿用现有 draft/search 状态，不建立重复设置系统。
9. “率定设置”负责编辑设置，“开始率定”负责提交计算；保存方案保存用户明确选择的参数，不能保存未完成任务的临时值。
10. 率定对象与后台实际能力一致。当前杜加流量产汇流率定与湖位蒸发系数率定可以组织成清楚的步骤，但不能仅改名为“全流域联合率定”。

2. 新资料自动采用同一规则。用户不再选择是否订正；更新观测不自动重拟合并改变历史采用系数。
3. 明确原始气象降水、陆域模型降水、湖面模型降水的空间含义与单位。
4. 湖面规则只作用于湖面采用量；不同时改变陆域降水、温度和蒸发。
5. 可以保留共享原数组加统一输入访问层，也可以生成专用湖面采用序列。选择一种清楚的数据路径，明确处理状态。
6. 湖面值必须恰好处理一次。预处理已经应用时，删除下游重复乘法；运行时应用时，不能上游再乘一次。
7. 同样原始数据和同样规则重复登记、合并、扩展或重试，采用值不再变化。
8. 统一首页湖面雨量、湖泊收支、模拟过程和导出采用值。原始气象仅在需要时另行查看并正确标注。
9. 检查站点降水是否真正用于现有偏差估计。若实现与采用方法记录不符，先修实际链路并量化变化；不得为满足“使用观测”把未经检验的点雨量直接铺满全流域。
10. 保留必要的处理依据与运行记录，普通页面不出现冻结、基准产品、派生产品等内部术语。

主要位置：
backend/forcing.py
backend/grid_simulation.py
当前湖面订正配置、气象合并与扩展调用。

完成判据：
固定规则自动应用；湖面一次订正，陆域保持其正确输入；重复更新结果不漂移；各页面和导出同源；新数据不要求用户重新选择校正版本。


【B05】统一模型输入解析与资料更新：按时期自动取数

后台 _input 已有自动匹配基础，但方案、历史模拟和资料页各自选择/排序版本；保存方案绑定旧 inputId；处理中间产物可能进入用户选择列表。

3. 率定取预热起点到评价结束的完整连续驱动，包含中间间隔；模拟取实际起算/预热到请求结束；续算核对末状态及后续驱动。
4. 统一检查变量、单位、累计量处理、时区、格网坐标及顺序、连续时次、完整日和订正规则兼容性。
5. 唯一业务入口不意味着覆盖唯一物理文件。已有运行保留真实输入身份，新计算使用当前有效资料。
6. 下载、登记、合并、处理和完整性检查全部成功后，再原子切换当前有效资料；失败/取消保持上一完整库可用。

8. 运行计划与提交使用同一解析结果。二者之间资料变化时重新核验，不能先按旧条件承诺复用，再按新条件运行。
9. 运行中的任务不随当前资料入口切换而变更输入。
10. 官方历史资料修订不覆盖旧成果的输入；续算检查状态之前的驱动前缀是否改变，变化时从有效起点重新计算。
11. 保留在线下载、断点续传、去重、失败重试；先核对已有活动请求，避免重复下载或注册。
12. 缺口具体到变量和时期，交由资料更新补齐，不让用户从多套内部产品中自行猜选。
13. 正常业务流程取消手动 NC 组装要求；必要的开发恢复能力不放在日常主界面。

【B06】连续模拟、自动初始条件与湖泊水量衔接

问题：
用户需要完整时期的水位、流量和状态；原始诉求包括模拟只在有观测处出现。当前已存在连续计算基础，应保护并打通自动初态与更新后继续计算。

解决方法：
1. 模拟时间轴由完整驱动、计算起点和请求结束确定；观测仅参与有依据的初始化、率定或评价，不决定是否输出模拟值。
2. 预热、率定、评价及中间时期连续推进状态，观测恢复或跨年时不重置湖位。
3. 已有内置方案保持其采用初态依据；新增更早期资料不静默改写旧方案结果。
4. 续算优先使用完整兼容末状态。空间、参数、驱动处理或历史输入改变后，按实际兼容性决定重算，不能强行复用旧状态。
5. 新时期由后台选择可用初始状态或合格主站观测，并记录实际采用时刻、数值和依据。无有效起算依据时明确最早可算范围，不造前期湖位。
6. 日均水位作为代表时刻初始化时，保留模型约定，不能称为真实瞬时观测。
7. 率定不能利用评价期才出现的观测初始化更早轨迹；不能用后期观测拟合偏差再宣称前期独立评价。
8. 主站 2021 年早期资料应完整可用。是否能从该期模拟，还取决于真实驱动与初态；先补齐和核对，不能只放开日期框就宣布支持。
9. 各分区产流、汇流输出与湖泊入流相接。杜加作为扎加内部断面不重复计入；融雪融冰已进入产汇流的部分不再次附加为入湖量。
10. 入湖流量按实际步长积分为水量；湖面降水和蒸发按所采用面积关系转为水量；湖泊蓄水变化和水位转换采用同一关系。
11. 实际存在的所有收支项、储量和符号一致。不得新增无依据的地下水或出流项吸收误差。
12. 每个结果记录实际时段、参数、输入、空间及初始状态身份；首页、图表、空间状态和导出均读取该结果。
13. 不为了消除前期空值而把无依据的初始化前湖位填满；明确陆域可计算起点与湖位实际起算点，普通用户由后台安排。

主要位置：
backend/grid_simulation.py
运行计划、状态保存、续算和成果摘要模块。

完成判据：
具备完整驱动和初态的观测空档持续有模拟值；跨窗口不重置；有效续算与整段计算在规定容差内一致；流量、水量、储量和水位关联正确；无重复加总和未来观测泄漏。


【B07】参数、率定和采用方案：界面与真实计算一致

问题：
空间分区被误当成每区一套独立参数；用户不能清楚识别采用值和率定初值；界面容易把现有局部率定夸大成全流域联合优化。

解决方法：
1. 核对当前内置配置的共用参数与分区覆盖关系；现有 duja 独立参数必须继续作用于其真实控制范围。
2. 后台解析实际有效参数，前端展示该解析结果；不能用一个通用表单值掩盖分区覆写。
3. 保存方案、人工试算、率定初值、率定结果及采用参数各自状态清楚，运行固定使用提交时的实际参数。
4. 只保存真实成功计算对应的参数与评价；失败或未完成任务不覆盖现有采用方案。
5. 当前支持的杜加产汇流参数率定与全湖蒸发系数率定明确表达。可以实现清楚的分阶段组合，但每阶段目标、可调参数和固定参数必须真实。
6. 率定时，每组候选参数对应的受影响状态必须由该组参数按相同初始化和预热规则计算；不得复用由其他参数生成且依赖已变参数的预热或末状态。只有确认与本次变化参数无关的子过程才可复用，并核对一致性条件。同次率定的湖位观测起点和依据保持一致，不为每组候选另选更有利的起点。
7. 未实现多目标联合优化时，不通过改标签宣称已具备。若后续实际增加该能力，需要目标函数、作用范围、约束和独立评价一起实现；本轮不无依据扩大范围。
8. 率定期与评价期独立，评价指标按共同有效日期计算。不能把观测缺口补零来提升样本量，也不能挑选不同任务的最优指标拼接。
9. 固定湖面降水规则在 B04/B05 管理，不通过让用户切换气象版本进行参数率定。
10. 更新空间归属或实际驱动后，复用现有参数先做必要对比，依据影响决定局部再率定。纯 UI 修改不启动新的参数搜索。
11. 形成一套最终采用的内置方案及真实配套结果；内部可保留必要复现依据，业务列表不再堆积试验版本。
12. “采用最优”的依据是本项目可用资料和已完成的有效比较，不能宣称未经检验的全局最优。
13. 修改后保留正常创建、复制、手动调参、试算、率定、保存、采用和回收的闭环。

主要位置：
backend/parameter_regions.py
backend/research_schemes.py
backend/grid_calibration.py

方案与率定结果记录模块。

完成判据：
编辑/保存/重开/运行的参数一致；杜加范围未被意外并入共用参数；参与率定的参数与实际搜索一致；采用结果与评价可追溯；已有正确方案不会随草稿变化。


【B08】约 2340.7 km² 残余区域：完成真实排水归属与计水处理

已确认问题：
grid_spatial.py 使用 dem-1km-raw.tif 和只向严格更低邻格行进的 D8；无下降方向、边界或无法追踪的情况归入 unresolved。定义了 external 类别，但当前追踪没有实际赋值分支。约 2340.7 km² 仍单独产流并排除在入湖量及湖泊水量之外，隐藏首页名称不代表完成计算。

解决方法：
1. 读取本机实际全流域边界、四河子流域、湖区、河网、DEM、杜加控制资料及当前空间产物。先核对坐标、单位、几何有效性、边界错位、重叠和遗漏。
2. 对现有残余区域分类检查：平地路由失败、分辨率问题、DEM 空值/边缘截断、伪洼地、真实闭合湖盆、其他水体、真实分水岭。
3. 优先使用现有可靠资料；已有更细 DEM 或经核实河网时据此复核。不得虚构具备 30 m 数据或 30 m 汇流能力，也不启动无边界精度升级。
4. 选择适当水文地形处理和河网/出口约束，解决伪洼地、平地和错误截断。保留真实闭合洼地与分水岭，不能无条件全域填洼强迫所有区域入湖。
5. 逐片确定去向：四条入湖河之一、湖周直接入湖、真实独立闭合水体或外排。存在实际湖间连通/溢流的，依据证据处理其连接，不能仅凭类别名称判定永不入湖。
6. 每种归属有具体空间与水文依据；面积闭合和数值残差接近零不能替代排水正确性。
7. 将确定入湖的区域纳入正确分区与汇流；确实不进入色林错的区域明确模型边界及独立水量去向，不无账目丢弃产流。
8. 同步更新计算分区、聚合单元、气象权重、成员映射和展示几何。地图湖周区域必须是实际分类后的区域，不是整个流域底面。
9. 核对湖面仅计一次、单元不重叠、所有面积有去向、分区合计与控制域一致；核对产流、汇流、各储量及湖泊水量闭合。
10. 用现有采用参数进行受影响重算，量化入湖量、湖位、雪冰状态和评价变化；有证据表明参数需调整时再做有范围的率定。
11. 形成最终采用配置后，生成与之对应的完整业务成果。不得把旧空间末状态直接当作新单元状态，亦不得沿用旧分数充当新结果评价。
12. 完成后同步替换历史模拟、首页、状态页和导出中的旧区域名称、长提示和旧计水范围。
13. 若个别结论仍缺真实资料，明确剩余区域、影响和具体资料缺口，完成其余工作；不得写成已全部解决，也不得继续将内部 unresolved 长期当作普通业务选项。

主要位置：
backend/grid_spatial.py
backend/grid_simulation.py
当前源 GIS、DEM、空间配置、聚合权重与成果元数据。

完成判据：
残余区域的实际去向有证据；计算和地图同一空间定义；无重复面积和重复计水；入湖组成与湖泊收支闭合；采用结果已按必要范围重算；任何真实未完成项明确记录。


【B09】空间、变量与状态展示的一致数据约定

问题：
AGG 单元已有同 ID 聚合几何机制，不能预判全部是编号错配；但不同变量的作用范围与前端选择映射不足，空间更新后还容易混用旧几何和状态。

解决方法：

2. 每个变量明确单位、作用范围、可用时间、时间含义和缺测标记；单元、分区、河流和湖泊对象分别映射。
3. 聚合单元保留真实成员和面积权重，展示可以适度简化但不得改变计算面积和水量归属。
4. 清楚区分气象格网、产流计算单元、DEM 与汇流空间尺度。0.1° 驱动格网不能冒称同尺度精细汇流；插值不能冒充新增实测空间信息。
5. 保留现有已采用的分区×高程带×冰川/陆面计算结构。只有实际归属或计算需要改变时才更新，不能为追求单元更多而盲目重构。
6. 状态帧不因观测缺测裁剪。空间版本不兼容时明确阻止错误拼接，并安排正确重算或读取。
7. 需要全时段固定色带时，从真实全时段数据计算或复用统计；不要把当前帧范围当全期范围。缓存合理失效，不每帧扫描全期。
8. 数值精度由物理意义决定，缺测与零区分。所选对象无几何或无该变量时返回具体原因。
9. 同一帧和目录支持复用，避免切换选择重复读取完整大文件。

主要位置：

状态查询、空间展示和变量目录 API
结果元数据与统计缓存模块。

完成判据：
对象、变量、单位、时间、几何和空间版本一致；不同范围变量均可正确定位；小斑块未被扩大；固定色带有真实全期依据；旧成果不会误用新几何。


【B10】资料、方案、成果与中间文件去冗余

问题：
内部输入产品和试验对象不断累积，部分仅因登记处理规则复制相同大数组；直接删除又可能损坏成果、状态和方案引用。

3. 确认无引用的失败中间产物、重复派生项和测试对象按项目现有可恢复机制清理；不新建巨大 archive 目录转移冗余。
4. 内容相同的驱动数组可通过共享存储或现有内容摘要复用；保证既有读取路径与权限正确，避免为一个订正规则再复制整份原始数据。
5. 普通列表只展示用户业务对象；必要的内部历史身份留在后台，不新增让用户管理版本的页面。
6. 清理不得影响正在运行或排队的任务，不能清空回收站，也不删除用户唯一原始资料。
7. 方案回收与成果回收保持各自关系，恢复时依赖完整；旧成果不因当前采用方案切换被改写。
8. 记录实际清理对象、原因与结果，使用一份简明清单即可。不要重复备份、生成多份审计副本或把所有旧版本改名继续保留在主列表。
9. 清理后检查默认打开、资料查询、成果读取、状态加载和新模拟的依赖完整性。

主要位置：
输入产品登记、方案/成果回收、资料目录及依赖管理模块；按当前仓库实际实现定位。

完成判据：
业务列表显著收敛；确认无用对象真正按规则清理；原始资料和已有成果仍可读；共享输入不再无意义重复复制；活动任务未受影响。

- 输入与运行：B04、B05、B06、B07；

B10 的实际清理应在引用关系明确、活动任务依赖确认之后进行。

步骤 4：完成跨层闭环
- F02/F05 对接 B01—B03；
- F06/F07/F10 对接 B04—B07；
- F03/F09 对接 B08—B09；
- F08 对接 B07/B10。

步骤 5：必要重算与采用成果更新
只有实际影响数值或空间的修改才重算。先用有代表性的短时期排除确定性错误；最终采用配置稳定后，完成一次必要的采用时期计算，统一更新首页、过程、状态和导出。需要局部率定时使用明确范围，不启动无限候选搜索。

步骤 6：集中验收、整理变更、提交推送
合并重复验证，满足本轮具体风险后停止扩展测试；形成简明结果说明并完成 Git 交付。

二、验证分级

级别 A：文案、样式、按钮、布局、定位
验证受影响页面、元素边界、点击、状态保存及实际数据对应。不跑全时段模型，不重率定。

级别 B：查询、缓存、资料解析与接口
验证代表性查询、边界和失败状态，以及优化前后采用值一致性；记录实际冷/热查询耗时。仅添加能覆盖真实缺陷的少量回归检查，不写只重复实现的测试。

级别 C：驱动处理、初态、参数应用、空间归属与汇流
验证数值正确性、输入处理次数、兼容状态、面积及水量闭合。按真正影响范围重算；最终采用成果随实际改变更新，不搬用旧分数。

构建成功只能证明构建通过，不能替代业务、数据或数值验收。现有可信验证能覆盖未改变的功能时直接复用，不重复做全套。

三、集中验收清单

A01 大屏与回放
- 用户普通窗口、全屏及曾触发故障的缩放条件下，四岸和收支完整，无越界遮挡和异常大空白。
- 来水分量、合计、水量、日期一致；早于四岸资料起点的日子表达正确。
- 时间轴比例真实，图表首末标签可读，快速拖动和播放不跨日拼接、不居中遮挡。

A02 监测与基准
- 在真实南岸覆盖时期查看原值、日值及独立分析状态；无固定偏移不清空观测。
- 无五站共同日、无时刻配对、日均不足和单站失败分别正确处理。
- 折叠分析不触发计算；同版本并发只算一次；逐日处理不重复查询版本。
- 原始值未被覆盖；基准转换有真实依据且按生效时段使用。

A03 资料与输入
- 同一资料按同一规则重复登记后，采用值不变化；湖面订正一次，陆域没有误乘。
- 新增气象资料后，方案和模拟按时期自动取数，无需选择产品。
- 更新失败/取消保持旧完整资料；旧成果输入仍可读取；历史修订后的续算正确判断。
- 站点降水用途与实际代码一致。

A04 方案、率定与连续模拟
- 新建/复制方案、改参数、试算、率定设置、运行、保存、重开、采用形成真实闭环。
- 运行参数与显示参数一致，杜加独立参数仍有效。
- 观测空档不切断具备驱动和初态的模拟；跨年不重置；没有未来观测泄漏。
- 若本轮改变了连续或续算逻辑，做一次针对性的续算与整段一致性核对。

A05 空间、状态与收支
- 所选真实单元、分区和湖泊对象能定位；图例范围、变量和单位正确。
- 残余区域归属有证据，计算面积无重叠遗漏，湖面和杜加不重复计水。
- 面积闭合、数值水量闭合和实际排水正确性分别核对。
- 新采用空间与成果一致，旧状态没有被错误接入。

A06 成果、清理与运行版本
- 真实成果可查看、导出、回收、恢复；引用未被破坏。
- 确认无用产物已按规则处理，正常页面无内部版本长列表。
- 实际运行的前后端确实加载本次修改，不能只改源码未更新服务所用静态资源。
- 保留活动任务，遵循项目构建方式；不因构建自动清空受保护目录。当前 build.emptyOutDir=false 的保护不要随意移除。

四、发现阻塞时的处理

1. 实际资料缺失、权限不足、外部服务失败或推送凭证不可用时，给出具体对象、已经尝试的步骤及确切影响。
2. 完成不受阻塞影响的前后端工作，保留可继续的状态。
3. 不用笼统“有风险”“尚未核实”替代具体结论；也不隐瞒真实尚未完成的项。
4. 只有必须由用户提供事实、资料或授权才能继续时，才集中提出必要问题。不要为普通 UI 细节、既有授权内提交或可逆实现反复确认。

5. 推送后核对远端提交确实包含本轮修改；本地 commit 不等于上传完成。

请按以下顺序简明汇报，不重新粘贴整份任务书：
1. 前端完成项：页面、用户可见变化、对应 F 编号。
