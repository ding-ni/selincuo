# 连续参考血缘与正式诊断读取：下一实施单

本单据为0.10最终安装验收期间的只读源码审查。没有改源码、原数据库、默认指针或既有科学证据；未运行新模型。实施前继续保留受保护窗口标准，不开放新发布。

## 2. 最小数据契约

建议先新增append-only `scientific_evidence_records(id,kind,payload)`与`continuous_reference_records(id,payload)`（命名可调整），迁移前SQLite在线备份。记录只由后端任务产生，评价请求仍只收ID；不能接受客户端scores/checks或任意路径。状态采用完整的`passed/failed/unknown/not-applicable`，缺证据为unknown。旧记录不覆盖，重做产生新ID。

所有证据至少绑定：producer实现SHA、协议及阈值SHA、被检成果ID与完整identity/request/result摘要、输入文件/前缀摘要、空间/参数/初始化/观测快照摘要、时间范围、实际逐值或物理量结果、产物文件/大小/SHA、失败原因。记录完成仅表示归档完整，不等同检查passed。

连续参考另保存：baselineReleaseId和schemeRevisionId、父窗口成果ID与六文件catalog摘要、源小时time/flow/continuousLakeVolumeChange摘要、原空间湖面积及来源SHA、固定锚点/高程工作基准、明确`method`、冻结共同质量观测及质量规则SHA、初始化日排除清单/日期SHA。连续参考是旧产汇流结果的派生连续湖位，不应伪装为`grid-continuous-v1`或改写旧模型identity。

## 3. 按依赖实施的工作包

### C1：连续参考生成与血缘验证，优先独立推进

新增`backend/continuous_reference.py`，在同一重任务队列加入只读派生任务。请求为baselineReleaseId、协议ID、已登记锚点配置ID，不接受用户任意锚点数值/日期或自由CSV。当前协议锚点为2023-04-20 12时、4544.03米，不能根据2025误差另选。先支持当前受保护旧参考，其他模型族暂明确不支持。

执行步骤：

1. 固定当前发布及父成果身份，核验其真实小时NPZ和自身空间版本、湖面积、已发布参数/输入/转换。只读提取time、flow、连续累计体积等小向量，不读全部陆面状态。
2. 确认time整小时连续且包含锚点；使用父成果自己的湖面积，以`h(t)=h0+[V(t)-V(anchor)]/A_parent`生成连续湖位，锚点前缺测。核验旧累计体积与实际完整小时净量的差分一致，不能使用只累计观测窗口活动小时的daily湖收支当完整净量。
3. 采用协议冻结质量观测（与候选共同，不静默用当前最新），完整24小时日均、缺测不插值，排除锚点初始化日；保存完整共同日期与样本值。原窗口初始化日仅属于旧窗口诊断，不再次删除连续参考后续每年窗口起点。
4. 输出连续reference JSON、日过程、月收支、源摘要与完整文件清单，末尾再核验发布及源身份未变后事务归档。方法标明`legacy-hourly-volume-fixed-anchor-derivation-v1`，不能标成“重新率定”或“完整模型独立重跑”。

完成标准：独立手算小序列与实际旧逐时向量交叉核对；与既有同口径E1差异须逐项解释面积/日期/质量规则，不因已有约0.079/0.104米就硬编码目标分数。第一次正式产物应重新产生指标并保存；不替换历史研究证据。

### C2：评价消费血缘，接在C1之后

让`evaluation_archive`通过显式reference reader读取正式连续参考，而不是放宽`baselineResultId!=release.resultId`的条件。验证reference记录的父发布恰是请求baselineReleaseId、父窗口result恰是该发布resultId、源摘要当前一致、协议/锚点/质量快照一致，才允许连续评价口径可比。任一缺项仍归档not-comparable及原因。

报告同时显示“受保护业务窗口成果”和“该业务基准的派生连续参考”；年度指标只能来自所选共同样本，不能把窗口0.065分数放入连续基准列。用新的身份结构区分referenceId与resultId，不重定义旧ID或modelFamily。

### D1：先接可独立核验的正式reader

新增`backend/scientific_evidence.py`，提供`read_verified_evidence(db,evidenceId,subject,protocol)`。可先支持下列已有资料充分的检查；即使其他检查unknown，也能真实归档局部结论，默认仍不变。

| 检查 | 生产与读取方法 | 通过依据与边界 |
|---|---|---|
| 参数范围 | 从真实冻结parameters与partitionParameters逐项核对定义、区域/物理范围，记录每项及触边 | 区域控制/全局默认不能混用；有限数、下界/上界逐项可追溯，触边不是自动科学通过 |
| 输入来源 | 复用现有输入/checkpoint前缀绑定，补原始sources/provenance文件、转换作用范围及SHA | 来源缺原件、历史修改、转换不明为unknown/failed；不以注册成功代替来源完整 |
| 完整产物 | 后台逐文件按Zarr manifest核验size/SHA，总摘要/shape/dtype/time覆盖和完整checkpoint一致 | 同时查缺文件/额外异常文件/partial/complete；仅目录存在或complete属性不够；分块流读、可取消 |
| 物理记账 | 按模型族独立读冻结小时量与初末状态重算陆面/汇流/湖面月表及最大残差 | 杜加仅计一次、雪融水不重复叠加、未核实区独立；储水使用S×FR、冰川外部源明示。容差须在协议冻结并说明数值/单位/尺度，不能临时放宽到结果以内 |
| 限制归档 | 检查报告包含适用控制域、未核实区、基准/零点、固定湖冰面积及外部裸冰等 | 文件存在与完整语义分别核对；只证明限制被披露，不能证明物理简化正确 |

`grid result.diagnostics`当前含`landGlacierMaxBalanceErrorMm/routingMaxBalanceErrorM3/lakeAreaKm2/partitions/lakeWindows`；不能按legacy `modelDiagnostics.catchmentBalanceMaxErrorM3`寻找然后以缺字段补零。模型自产diagnostics可用作交叉检查，但正式reader应重新核验关键收支。

### D2：严格续算证据生产器，接D1完整性之后

已有`scripts/grid_extension.py`及全量导出验证是研究/工程脚本；其JSON布尔不直接灌入正式checks。新增受控`continuation-verification`任务：冻结同一原始起点、参数、输入历史前缀、观测及初始化，执行完整与分段两条路径；比较重叠期间全部保存变量及完整末状态、来源调蓄/河道队列，保存最大差、位置、shape、dtype、mask。真实纯延伸也比较同一历史前缀到末状态，不仅比较湖位或最后土壤均值。

不允许伪造旧模型SHA延续；旧任务实现不匹配时保存`not-applicable/unknown`并要求当前实现重新产生一对可复现成果。先用小输入测试，再做真实最终候选。后台同一重队列，完成前不能把状态设True。

### D3：初态稳定性专项，外部资料受限但可先实现读取契约

可先实现完整schema、干湿/预热成对身份校验与不通过结果reader，使用已有30天对照明确失败。正式通过需要真实同源2023/2022/2021/2020逐档驱动与25%/50%/75%初态；锚点仍固定2023-04-20 12时，不借2025观测反挑初态。真实缺年为unknown，不能重复拼接已有年冒充。

数值门槛沿当前PROTOCOL：正式期湖位最大差≤0.01米，杜加流量差RMSE≤同期观测均值1%。必须保存成对日期、覆盖、观测均值、最大差发生时刻、每档真实来源；不是只存passed布尔。更长两档未提供时，最短预热“已稳定”结论不成立。

### D4：评价聚合与前端表达，最后接入

仅消费正式reader返回的已校验记录，生成checks与stability真实数值。身份、时段或协议错配时不复用，缺诊断继续unknown，检查失败仍可归档。页面分清“报告完整”“共同口径可比”“指标有改善”“发布准入通过”四件事；任一阶段失败不使默认切换。

当前`freeze_revision(runtime_evidence)`是内部helper，也不能直接把调用方任意字典视为reader认证。应在内部按evidenceId加载验证并保存hash，而不是开放前端提交`fullArtifactsVerified/strictContinuationVerified`。

## 4. 必要测试和交付验收

1. 连续reference：固定小体积手算湖位/日均；缺锚点、时间缺口、源文件/面积/参数/转换改动拒绝；窗口年重锚不能混入；旧窗口255日评分原样保存，连续共同日另列。
2. 血缘：其他发布/其他父成果/任意复制CSV/客户端宣称关系拒绝；发布在队列期间变化不提交；取消、崩溃和半文件不生成完整记录；重复证据组合幂等并校验产物。
3. reader：改一个Zarr chunk、截短数组、检查点冲突、NaN/shape/队列缺项、错误单位和错协议均拒；参数不同区域或输入前缀不同不得借证据。
4. 记账：小例独立手算杜加/扎加不重复、融雪只在产流内计、未核实区不入已核实总量；自由水按S×FR；窗口活动小时和完整连续收支分开。
5. 续算：完整/分段/纯延伸全部变量与末状态逐值或冻结容差一致；改历史值或实现SHA明确拒，不能只比较最后湖位。
6. 初态：真实已知不稳定样本必须返回failed；缺真实长预热返回unknown；刚好门槛边界、观测均值无效/缺测、不同锚点/评价期拒混。
7. 一次完整隔离HTTP闭环：产生连续reference→正式reader归档→共同日评价→保存失败原因与下载SHA→刷新/跨页保持；即使所有工程检查通过，真实当前候选仍因科学指标/初态不足不能升级。
8. 发行与恢复：新证据清单、reference、观测33来源与原始文件成套；备份恢复后ID/SHA和结论不变；源码、EXE及手册版本一致。安装测试不能代替科学实验。

以上交付可分批完成，不以缺原生地形或长期资料阻塞C1/C2/D1结构实现。新发布门槛维持关闭；只有正式reader、连续参考血缘、任意修订端到端运行和科学多指标全部通过，才另行评审`runtime_supports`与发布流程。本单据不提供发布授权或通过结论。
